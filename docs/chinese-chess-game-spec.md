# 中国象棋游戏实施规格

## 问题与目标
使用 GDevelop 开发中文中国象棋游戏，采用原生事件，优先复用 prefab、behavior、external event 和 external layout。游戏独立存放于 `/Users/zhouzhipeng/ChineseChess`，不修改引擎接口与序列化格式。已创建 1280×900 项目并在编辑器打开，目前是空白初始化项目。

## 当前与预期行为
当前仅有默认 Game 场景。目标提供本地双人完整对弈：红先黑后、选择与换选、合法落点、吃子、将军提示、禁止自陷将军、将帅照面、将死与困毙判负、悔棋、重新开始、认输、和棋、棋谱列表、最近一步标记和规则说明。支持鼠标和触摸。首版不包含联网、账号、等级系统或专业竞赛长将长捉裁决；重复局面提示双方和棋。电脑对弈不作为首版验收前提。

## 规则
车直线且路径无子；马日字并检查蹩马腿；象田字检查象眼且不过河；士斜走九宫；将帅在九宫直走一步；炮移动无阻、吃子恰隔一子；兵卒前进一步、过河后可横走且不能后退。每次候选移动都在棋盘副本模拟，检查己方将帅是否受攻击。终局枚举当前方所有合法移动，无可走判负。历史记录保存移动、吃子、轮次及终局状态以支持完整撤回。

## 文件与职责
- Game 场景：场景生命周期只链接外部事件。
- Xiangqi 扩展：Piece prefab 提供棋子视觉、选中态和最近移动态；BoardCoordinate behavior 封装行列与屏幕坐标转换；ActionButton prefab 统一交互与按钮状态。
- external events：Initialize、Input、MoveRules、AttackDetection、LegalMoves、CommitMove、History、Endgame、Presentation，各自有明确输入输出变量与执行顺序。
- external layouts：Board（棋盘与河界）、MatchPanel（双方与轮次）、Toolbar（操作区）、RulesDialog、ResultDialog。界面通过实例化布局加载，避免主场景堆叠 UI。
- assets：本地 SVG 木纹配色棋盘、圆形棋子与装饰；不依赖在线资源。
- tests：规则边界与完整交互的确定性 gameplay tests。

## 界面
暖米色棋盘、深墨绿背景、朱红与墨黑棋子、金色选中描边；棋盘居左，右侧放对局状态、棋谱和操作按钮。中文字体使用系统可用字体并验证汉字显示。合法落点用小圆点、可吃目标用环形标记。弹窗显示明确结果与再来一局按钮。

## 数据与接口
Board 使用 90 格结构化变量；Piece 保存 Id、Side、Kind、Row、Column、Alive。Match 保存 Turn、SelectedId、Phase、Winner、MoveCount；History 为结构数组。只使用项目内部 API，不新增公共引擎 API；无格式迁移与兼容性影响。

## 性能与错误处理
仅选中、提交或撤销移动时计算合法走法；攻击检测遍历最多 32 枚棋子，禁止每帧全盘搜索。非法输入保持棋盘不变并显示提示；弹窗时屏蔽棋盘操作；重开清空历史和临时选择。初始化检查双方将帅与棋子数。

## 实施与验证
1. 先实现复用组件、外部布局与静态画面。
2. 用原生事件实现规则、攻击检测与移动提交。
3. 加入历史、终局与操作弹窗。
4. 运行结构验证，提交项目源文件，再重载编辑器。
5. 暂停预览并逐帧测试选择、移动、吃子、悔棋、重开；截图检查中文与布局。
6. 测试蹩马腿、塞象眼、炮架、过河、九宫、自将、照面、将死和困毙。通过运行验证后方可声明可玩。

## 备选与权衡
JavaScript 规则库实现更快，但不利于用户原生事件复用要求，因此优先事件函数和外部事件；若原生能力不足，先记录具体限制再决定最小必要代码。棋子采用 prefab 而不是 14 套独立对象，统一状态与交互。
